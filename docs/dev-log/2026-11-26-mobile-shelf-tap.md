# 2026-11-26 프론트엔드 개발일지 — 모바일 책장 직접 탭 검증

## 작업 범위

사용자는 다음 마무리 작업이 간단하면 진행해 달라고 요청했다. PR #41의 head 8901120에서 필수 Validate repository 성공을 먼저 확인했다. 기존 월별 책장 기능의 남은 검증을 같은 PR에 추가하고 필수 CI 후 병합하는 범위로 진행한다.

## 빠져 있던 경로와 선택

기존 모바일 검사는 터치 조이스틱으로 8월 책장에 접근했지만 선반을 여는 동작에는 Enter를 사용했다. 이 상태에서는 GardenNextPlot에서 실제 책장 메시로 이어지는 포인터 이벤트가 빠져도 검사가 통과할 수 있다. 제품 코드의 결함이 발견된 것은 아니며, 실제 사용 경로에 맞춰 검사만 보강했다.

8월 시나리오에 한해 Canvas에 실제 touchscreen 탭을 보낸다. 고정된 iPhone 13 뷰포트와 관찰한 책장 몸체를 기준으로 너비 0.51, 높이 0.29 지점을 선택했다. Three 내부 상태나 테스트 전용 API로 선반을 열지 않는다. 접근 입력은 touchEnd로 끝낸 뒤 캡처·탭을 수행한다.

다른 시나리오는 기존 Enter 검사를 유지해 키보드 경로도 보존한다. 이 탭 경로가 실패했을 때 Enter로 대신 여는 처리는 없다. 탭 다음의 선반 제목, 8월 문맥, 안내서 자동 실행 없음, 해당 월 우선 14권과 다른 월·이전 연도 페이지, 8월 산책 복귀 검사가 성공해야 통과한다.

## 검증

Node 26에서 pnpm check가 통과했다. 포맷·lint·타입·단위 50개·저장소 검증·프로덕션 빌드를 포함한다. `CI=1 pnpm test:e2e tests/e2e/monthly-bookshelf.spec.ts --project=mobile --grep 'reads local' --retries=0`는 15초에 재시도 없이 통과했다. 프로덕션 빌드에서 실제 모바일 터치로 조이스틱과 캔버스 탭을 수행했다.

독립 리뷰는 탭 이후 선반 검증 이전에 키보드 우회가 없고, 이동 입력을 끝낸 뒤 탭한다는 점을 확인했다. 병합을 막는 발견 사항은 없었다. 새 head의 전체 필수 CI는 PR #41에서 확인한다. 앱 기능·저장 형식·일기·이미지는 변경하지 않았다.
