# 2026-11-10 개발 일정과 결과

| 순서 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 날짜별 일기 저장 PR의 필수 CI를 확인하고 병합 | 완료 |
| 2 | 저장 날짜를 월별로 묶고 일기장에서 날짜를 골라 다시 열기 | 구현 및 검증 완료 |
| 3 | 같은 날짜 목록을 월별 책과 일별 꽃에 연결 | 구현 및 검증 완료 |

1단계에서 저장 PR #23을 Squash 병합했다. 2단계는 병합된 main에서 별도 브랜치로 시작했다.

IndexedDB의 날짜 키를 읽어 최신 월과 최신 날짜 순서로 묶었다. 날짜 목록을 만드는 데 본문이나 사진을 읽을 필요가 없으며, 월 정보는 조회할 때 계산하므로 기존에 저장한 일기를 그대로 사용할 수 있다. 같은 날짜에 다시 저장해도 날짜 키는 하나다.

일기장의 ‘저장한 날짜’ 목록으로 월별 묶음을 확인하고 기존 날짜 선택 흐름을 통해 해당 기록을 열 수 있게 했다. 일기장을 열거나 저장이 완료되면 목록을 갱신한다. 조회에 실패하면 다시 시도할 수 있다.

로컬 전체 검사와 데스크톱·모바일 Chromium 테스트 24개가 통과했다. 새 브라우저 검사에서는 월 경계를 넘는 기록, 최신순, 같은 날짜를 다시 저장한 뒤 중복 없는 목록, 미저장 초안 제외, 새로고침 후 선택과 복원을 확인했다.


## 3단계 · 정원에서 저장한 기억 읽기

PR #25의 필수 CI가 통과한 뒤 병합했다. 기존 날짜 키 조회를 책장과 꽃밭에 재사용했다. 저장 트랜잭션이 끝나면 정원의 목록을 갱신한다. 같은 날짜를 다시 저장하면 키가 그대로이므로 꽃은 한 송이만 표시된다.

책장은 안내서 슬롯을 유지하고 한 페이지에 기록 책을 최대 14권 표시한다. 월별 책을 열면 그달의 저장 날짜가 나온다. 꽃밭은 한 페이지에 날짜별 꽃을 최대 여섯 송이 표시한다. 꽃을 누르거나 같은 페이지의 날짜 목록에서 선택하면 저장한 글과 사진을 읽을 수 있다. 페이지를 이동하면 이전 기록도 열 수 있다.

기록 읽기는 읽기 화면을 사용해 편집 중인 초안과 구분한다. 정적 지도에서도 책장과 꽃 목록을 열 수 있고, 읽기 화면을 닫으면 키보드 포커스가 출발점으로 돌아간다. 작업은 [Issue #26](https://github.com/Debuging-JunSeoPark/memory-garden/issues/26)에서 추적한다.

로컬 전체 검사와 Chromium E2E 26개가 통과했다. 새 시나리오는 정적 지도에서 저장, 같은 날짜 재저장, 꽃밭 다음 페이지, 새로고침 후 월별 책에서 읽기, 닫은 뒤 포커스 복귀를 검증한다.
