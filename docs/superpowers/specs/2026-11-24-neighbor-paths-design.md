# 이웃 월 정원으로 이어지는 여러 산책길

사용자가 요청한 후속 순서에 따라 PR #37 병합 다음 단계로 이동 경로를 확장한다. 기존에 조율을 맡기고 순차 진행을 요청한 범위이며, 새로운 서비스나 저장소를 도입하지 않는다.

## 의도와 범위

3열 지그재그 월 배치와 월별 계절·일기·꽃은 그대로 유지하고, 열린 땅의 상하좌우 이웃을 모두 다리로 연결한다. 11월에는 11개 땅과 15개 다리가 생긴다. 11월에서 8월로 바로 걸을 수 있으며 12월 자리나 대각선에는 길이 생기지 않는다. 땅 위에서는 방향을 선택할 수 있어야 하고 모든 다리를 왕복할 수 있어야 한다.

각 땅의 책장은 다음 PR이다. 이번에는 기존 책장이 북쪽 입구를 막는 문제와 동쪽 화단의 통행 문제를 함께 해결한다. 안내 UI나 순간이동 버튼은 추가하지 않는다.

## 접근 방식

- 기존 월 순서 연결만 유지: 가까운 땅으로 돌아가는 불편을 해결하지 못한다.
- **열린 상하좌우 이웃 연결 — 채택:** 사용자가 요청한 여러 갈래 길과 기존 3열 배치를 함께 만족한다. 다리 생성 결과를 렌더링·지면·난간이 공유한다.
- 대각선 또는 중앙 허브: 기존 배치와 다리 규격을 크게 바꾸고 길 교차가 필요하므로 이번 범위에 맞지 않는다.

구체적인 좌표와 디딤돌 모양은 구현자가 정한다. 책장과 나무는 모서리 쪽에 두고, 화단과 벤치는 중심 통로를 비운다. 모델과 충돌 판정은 같은 배치 값을 사용한다. 연결된 방향에만 낮은 디딤돌을 그려 출구를 보여 준다. 책장 위치 변경 시 확대 카메라의 상대 구도도 유지한다.

## 제약과 검증

Next.js·R3F 기반의 기존 FSD 슬라이스 안에서 구현한다. 의존성·저장 형식·일기 데이터는 변경하지 않는다. 산책의 주변 땅 렌더링과 프레임 ref 사용을 유지하며, 다리의 React key는 양 끝 인덱스를 함께 사용한다.

단위 검사는 1·2·3·4·11·12월의 연결 수, 중복·대각선·빈 슬롯 배제, 15개 다리의 양방향 보행과 난간을 확인한다. 브라우저에서는 데스크톱·모바일로 새 11월↔8월 길을 실제 걸어 보고, 책장 접근·확대·안내서·원래 월 이동 회귀를 확인한다. 전체 검사와 개발일지 작성 후 Issue에 연결한 별도 PR로 올린다.
